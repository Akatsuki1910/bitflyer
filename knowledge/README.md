# knowledge/

Claude が仮売買の判断をするときに読む知識と、判断を外したときの振り返りを置く場所です。

| ファイル | 中身 | 誰が書くか |
|---|---|---|
| [`playbook.md`](playbook.md) | 売買判断ハンドブック。実証研究と、このリポジトリの検証結果から作った原則 | 初版は文献調査。以降は教訓が確認できたときだけ改訂 |
| [`lessons.md`](lessons.md) | 教訓ノート。外れた判断の原因と修正の仮説 | 見立てタスクが毎回読み、必要なら書き足す |

## 判断して、外れたら直す流れ

```
          ┌──────────── playbook.md ◀─── 昇格（3回以上確認 / 明白な誤り）
          │                                    │
          ▼                                    │
  ① 判断を書く ─────────▶ ai_calls.json        │
    （確信度・根拠の ID・反証条件）   │          │
                                   ▼          │
  ② GitHub Actions が次の回で仮想口座「Claudeの判断」として約定
                                   │          │
                                   ▼          │
  ③ score_calls.py が約24時間後の価格で機械的に採点 ─▶ ai_scorecard.json
                                   │          │
                                   ▼          │
  ④ 外れを分類する ── ノイズ → 記録するだけ     │
                   └─ 根拠の誤り / くり返し → lessons.md に仮説 ─┘
```

大事な決まりが3つあります。

1. **採点は機械がやる。** Claude が自分の判断を自己採点すると甘くなるので、`src/score_calls.py` が価格だけで判定します
2. **1回の外れで原則を書き換えない。** 24時間の値動きはほぼコイン投げなので、根拠が妥当だった外れはノイズとして扱います
3. **過去の判断と教訓は消さない。** 撤回した教訓も理由と一緒に残します

ルール27口座（`src/strategies.py`）の判断にはこの知識は使いません。
あちらは「Claude の判断に実力があるか」を比べるための基準として、計算式のまま動かし続けます。
